## 2. 劇本系統

| 元件 | 說明 |
|---|---|
| 劇本檔 | 地圖 JSON ＋ 初始單位與建築 ＋ 觸發器 ＋ 對話，放在 `src/data/campaigns/` |
| 觸發器條件 | 時間、進入區域、單位或建築死亡、資源達標、建築完成、變數比較、計時器 |
| 觸發器動作 | 對話、生成單位、改目標、勝利／失敗、鏡頭移動、改外交、給資源、播武將特寫、改天氣與風向 |
| 對話 | 立繪 ＋ 書法名牌 ＋ 打字機效果；可跳過；遊戲時間可暫停 |
| 目標面板 | 主要／次要目標清單，達成時打勾音效 |
| 編輯器 | DEV 工具內建簡易地圖與觸發器編輯器（M6），匯出 JSON |

觸發器在模擬層執行，所以戰役也是確定性的，可重播。

## 3. 多人連線（Phase 2，M7）

### 3.1 模型：確定性 lockstep（和世紀帝國 II 一樣）

| 項目 | 設計 |
|---|---|
| 同步方式 | 每位玩家只送「指令」，所有客戶端各自跑同一套模擬 |
| 回合 | 1 turn ＝ 2 tick（200ms）；指令排在 turn ＋ 2 執行；依 RTT 動態調整 100–400ms |
| 伺服器 | 只做中繼：轉發指令、對時、房間管理，**不跑模擬** |
| 不同步偵測 | 每 N 個 turn 交換狀態雜湊；不一致就記錄重播檔並回報 |
| 斷線重連 | 下載種子 ＋ 指令紀錄，快轉追上進度 |
| 大廳 | 房間碼或分享連結；2–4 人；空位可放 AI；隊伍設定 |
| 跨平台 | PC 與手機同房；turn 長度自動配合最慢的玩家 |
| 防作弊 | lockstep 天生防改數值；開全圖外掛無法完全防，排位賽才考慮伺服器驗證 |
| 觀戰 | 延遲 2 分鐘的觀戰；重播分享 |

### 3.2 中繼伺服器選型 **[待確認]**

| 方案 | 優點 | 缺點 |
|---|---|---|
| Cloudflare Workers ＋ Durable Objects（推薦） | 全球低延遲、WebSocket 原生支援、便宜、免維運 | 需要 Cloudflare 帳號 |
| Supabase Realtime | happyFarm 已在用，帳號現成 | Realtime 頻道的延遲和訊息頻率不太適合 RTS |
| 自架 Node（ws） | 完全掌控 | 要自己維運主機 |

Phase 1 的 `src/net/` 先做「本機假網路」實作（同一個瀏覽器裡開兩個模擬，互傳指令），在單機階段就能測 lockstep 邏輯。
